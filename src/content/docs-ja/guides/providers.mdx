OcHub はアプリごとに接続を分けて保存します。Claude Code の接続が
Codex に自動で現れることはありませんが、**アプリへコピー**で対象形式の新しい設定を
生成できます。

## 既存設定を検出する

アプリページを開くと、OcHub はツールの現在の実設定を読み取ります。

- 認識できる接続は「直接接続」に表示されます。
- ツールに存在するが現在ではない項目は「追加済み」と表示されます。
- 使用中の接続は「現在」と表示されます。
- フォームで完全に表現できないカスタム項目は、保存前に書き込みプレビューを確認します。

## 編集、保存、適用

接続エディターには**基本**、**詳細**、**設定ファイル**の 3 つの表示があります。
保存と適用は下部に固定されています。**設定を確認**は設定ファイル、**アプリへコピー**は詳細にあります。プリセットはドロップダウンで選択し、新規接続では基本、既存接続の編集では詳細に表示されます。基本では通常の接続を設定し、詳細では
対象アプリが対応する追加項目を編集します。表示を切り替えても設定済み項目は無効になりません。

| 操作 | 実際の結果 |
| --- | --- |
| OcHub に保存 | 未完成の項目や不正な原文を含め、独立した編集下書きを保存。正式な接続と対象設定は変更しない |
| 設定を確認 | 書式、必須項目、ローカル制約を確認。モデルへの要求やアカウント権限の検証は行わない |
| アプリに適用 / アプリに書き込む | 対象の下書きリビジョンを保存・検証して書き込み、完了後に正式な接続を確定 |
| 対象アプリでインポート | 外部アプリでの確認が必要。確認待ちの間は下書きを保持 |

通常の保存ではエディターを閉じません。アプリページの下書きから後で再開できます。
**Command+S / Ctrl+S** も同じ保存操作で、原文エディター内の不正なテキストも保存できます。
キー入力ごとの自動保存は行いません。変更した内容から離れるときは、編集を続ける、変更を破棄、
保存して移動のいずれかを選びます。

下書き保存、設定書き込み、クライアントによる読み込みは別の状態です。適用に失敗した場合は
失敗箇所を確認し、保持された下書きを修正します。切断時は現在の入力をメモリに保持し、再接続まで
保存・適用できません。メモリ上の入力は保存済み下書きではありません。

**今回の適用を取り消す**は、完全な書き込み記録がある場合だけ表示されます。
取り消しでは現在の状態が適用直後と一致するかを確認し、その後の変更を上書きしません。
共有ファイルでは別の接続への新しい変更も取り消しを妨げる場合があります。資格情報、
ゲートウェイの準備、外部インポートなど、復元範囲が揃わない操作には表示されません。

## 日常の操作

接続行には切り替えやツールへの追加を表示します。行末の矢印を開くと、編集・複製・削除を選べます。もう一度押すと閉じます。

| 操作 | 用途 |
| --- | --- |
| 編集 | アドレス、キー、モデル、メモ、高度な項目を変更 |
| ドラッグで並べ替え | リストとシステムメニューの表示順を変更 |
| アプリへコピー | 元の接続を変えず、対象形式の独立した下書きを作成。対象ページで確認して適用 |
| ツールに追加 | 現在の接続を変えずに事前登録 |
| 切り替え | 直ちに現在の接続に設定 |
| ツールから削除 | OcHub データを残し、実設定だけから削除 |
| 削除 | OcHub から完全に削除 |

現在使用中の接続を削除する前に、別の接続へ切り替えます。

## 公式ログイン

**公式ログインを使用**はサードパーティーの Base URL や API キーを書き込まず、
ツール自身のログイン状態を利用します。

- Claude Code または Codex ですでに公式アカウントへログイン済み。
- サードパーティー API から一時的に公式サービスへ戻す。
- ツール固有のアカウントやサブスクリプション機能を維持する。

Codex では `auth.json` と `config.toml` の両方が現在の接続バージョンに含まれます。
OcHub 外で変更した内容を残す場合は、別の接続へ切り替える前に差分を確認して新しい
バージョンとして保存します。

## アプリ固有設定

アプリページ右上の**アプリ設定**を開きます。

| アプリ | 主な設定 |
| --- | --- |
| Claude Code | カスタム設定ディレクトリ |
| Codex | 履歴統合、既存セッション移行、カスタム設定ディレクトリ |
| OpenCode | カスタム設定ディレクトリ |
| OpenClaw | カスタム設定ディレクトリ |
| Hermes | カスタム設定ディレクトリ |
| Grok Build | カスタム設定ディレクトリ |

カスタムディレクトリは、設定、MCP、セッション履歴の読み取り先を変更します。保存後に
OcHub と対象ツールを再起動してください。

Codex の履歴設定はチェックボックスで変更し、その場で保存されます。
**Codex のセッション履歴を統合**を有効にすると、
**既存の Codex セッションを取り込む**が表示されます。

ディレクトリの入力は**ディレクトリを保存**するまで下書きです。履歴のチェックボックスを
変更しても入力は保持されます。保存中に続きを入力した場合は、もう一度
**ディレクトリを保存**して新しい内容を保存します。

## エディター内のチェック

**設定ファイル**には候補内容とパスを表示します。最終ファイルは対象環境の既存設定と統合され、
プレビューがファイル全体の無条件な置き換えを意味するわけではありません。長い行は横にスクロールできます。

**編集**で原文を変更し、**編集内容を更新**で解析できる内容をフォームへ統合します。
対象アプリにはまだ書き込みません。**編集に戻る**でもテキストは保持されます。不正な内容も
下書き保存できますが、構造化フォームへ戻るには書式を修正します。未対応のキーは保持され、
書式やコメントの完全な維持は対象アプリの形式とアダプターに依存します。

**共通設定**はアプリ単位の共有スニペットです。同名キーは実際の統合規則に従って接続値を
上書きし、既定値の継承ではありません。変更は利用する接続に影響します。下書き保存では
共有内容を変えず、明示的な適用時に確定します。

対応する組み込みアプリには **URL をテスト**、**モデルを取得**、**残高を確認**もあります。
HTTP 応答、モデル一覧、互換の残高 API の確認であり、実際のモデル要求の成功を保証しません。
設定を変更したら確認し直し、対象ツールの実リクエストで検証してください。

## 外部で設定が変更された場合

OcHub は現在の接続を、保存済みの設定バージョンとして扱います。切り替え前に、その
バージョンとディスク上の現在のファイルを比較します。

1. 左右のファイル差分を確認します。赤は保存済みバージョン、緑は現在のファイルです。
2. **新しいバージョンとして保存**を選ぶと、現在のファイルを現在の接続へ保存してから
   切り替えます。後で戻ると、この新しいバージョンが復元されます。
3. **保存済みに戻す**を選ぶと、ディスク上の変更を破棄し、保存済みバージョンを復元して
   から切り替えます。
4. **キャンセル**では OcHub のデータも現在のファイルも変更しません。

この処理は、Claude Code、Codex、Grok Build、Kimi Code、切り替え型プラグインなど、
OcHub が実設定を読み取れるすべての切り替え型アプリに適用されます。Codex では
`auth.json` と `config.toml` を別々に表示し、不正な JSON の `auth.json` も原文のまま
差分、保存、復元の対象になります。

OcHub、cc-switch、手動エディターで同じファイルを同時に編集しないでください。

## 新しい接続を確認する

編集内容を適用した後、または既存の接続を切り替えた後：

1. 生成ファイルとパスを確認。
2. 「設定書き込み済み」を確認するか、外部アプリでインポートを確認。下書き保存だけでは書き込まれません。
3. 対象ツールを完全に再起動。
4. 新しいプロバイダーとモデルを選択。
5. 短いリクエストを送信。
6. ツールエラー、OcHub 使用量、上流ログを確認。

| 問題 | よくある原因 |
| --- | --- |
| 接続がない | 下書きの保存のみで未適用、またはディレクトリ違い |
| 別項目を上書き | 共存アプリで Provider ID が重複 |
| 401 | キー、環境変数、起動環境の不一致 |
| 404 / ボディエラー | バックエンド、プロトコル、API モードの誤り |
| モデルは見えるが失敗 | ID、コンテキスト、権限の不一致 |
| 高度な保存に失敗 | JSON/YAML ノード型の誤り |
