サイドバーの**概要**から、設定を変更せずに 1 つの環境を確認できます。ナビゲーション上部の
ワークスペース選択で、本機または接続済みのリモートノードを選びます。変更後は**更新**を
押してください。概要は保存済みデータと現在の Gateway 状態を読み取ります。上流への検査や
新しいセッションの取り込みは実行しません。

## 設定上の経路を読む

**設定上の経路**には Gateway ルート、有効な候補数、モデルルール数が表示されます。
ルートや上流で検索し、**詳細**から関連アプリと上流インターフェースを確認します。
設定を変更するには**ルート管理**から既存のプロバイダーとルートのページへ進みます。

表示されるのは現在の設定上の関連であり、過去のリクエストが実際に通った経路ではありません。
インターフェースを明示しないルートでは、モデルとプロトコルのルールに従って、すべての有効な
インターフェースを候補にできます。参照先が存在しない場合は修正のための注意が表示されます。
プレビューの件数制限はページ上で確認でき、全件は対応する詳細ページで表示できます。

Gateway の表示は待ち受けプロセスの稼働状態です。インターフェースの到達性は観測時刻を持たない
キャッシュ値です。到達可能でも認証に失敗したり、モデルを利用できなかったりします。
HTTP 401、403 も到達可能と扱われる場合があります。最新の結果が必要なら、接続または上流の
詳細ページから既存の診断を実行してください。

## アプリの接続と下書きを確認する

**アプリの接続**には保存済み接続、現在の選択またはツールに追加済みと記録された項目、
保存済みの編集下書き数が表示されます。**開く**からそのアプリのページへ進みます。

これは OcHub の記録であり、クライアントプロセスが設定を読み込んだ確認ではありません。
Gateway の関連がない接続も自動的に直接接続と判断されません。接続方法は詳細で確認します。
選択情報が古くなっている場合もアプリのページで確認してください。

## 使用量と最近の記録を理解する

**24 時間**、**7 日**、**30 日**を選べます。**記録済み使用量**には記録数、推定費用（USD）、
キャッシュを含む処理 token、記録数の推移が表示されます。**数値を表示**で各期間の値を表として
確認できます。推移にはデータを提供するノードの
時刻帯を使います。既存の重複排除ルールに基づき、Gateway／proxy の収集記録と取り込み済み
セッションを含みます。未収集の活動は含まれず、推定費用はプロバイダーの請求額ではありません。

**最近の記録**は、指定期間に保持されている詳細を最大 10 件表示します。取得元ラベルで収集と
セッション取り込みを区別します。取り込みセッションには信頼できるリクエスト所要時間がありません。
最近の失敗に関する注意はこのプレビューだけの件数であり、期間全体の失敗総数ではありません。

**使用量を表示**、**全記録**、**セッションを開く**から対応するページへ進めます。一部の読み取りが
失敗した場合、その部分だけにエラーが表示されます。欠損データを 0 には変換しません。
環境がオフラインになるとスナップショットを消去し、更新処理を本機へ切り替えることもありません。

## リモートノードの概要

ノードが概要（`overview-v1`）に対応し、接続、Gateway 状態、使用量の読み取りを許可している
必要があります。古いノードで読み込めない場合は更新して再接続してください。
機能が利用できなくても本機で代わりに処理することはありません。

概要は各セクションを個別に読み取ったスナップショットであり、全プロセスの原子的な監査ではありません。
接続診断は[リモートノード](/ja/guides/remote-nodes)、ルート変更は
[ルーティングレシピ](/ja/advanced/routing-recipes)を参照してください。
自動化には、同じ読み取り専用情報を返す
[`ochcli overview` コマンド](/ja/developer#概要スナップショットを読む)を利用できます。
