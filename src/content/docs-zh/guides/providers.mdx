OcHub 为每个应用分别保存连接。Claude Code 中的连接不会自动出现在 Codex 中，但可以
使用“复制到应用”转换为目标工具的格式。

## 自动发现已有配置

打开应用页面时，OcHub 会尝试读取该工具当前的实时配置：

- 能识别的连接会出现在“直接连接”列表中。
- 已写入工具但尚未设为当前项的连接会显示“已添加”。
- 当前正在使用的连接会显示“当前”。
- 无法完整识别的自定义字段应先查看写入预览，避免重新保存时丢失。

## 编辑、保存与应用

连接编辑器分为**常用**、**高级**和**配置文件**，底部始终保留检查、保存和应用操作。
常用页完成接入，高级页保留应用支持的附加参数；切换页面不会关闭已经设置的高级选项。

| 操作 | 实际结果 |
| --- | --- |
| 保存到 OcHub | 保存独立编辑草稿，包括未填完的字段或格式错误的原始文本；正式连接和目标配置不变 |
| 检查配置 | 检查格式、必填项和本地约束；不发送模型请求，不验证账号权限 |
| 应用到应用 / 写入应用 | 保存本次草稿版本，校验并写入目标；只有应用完成后才提交正式连接 |
| 在目标应用中导入 | 由外部应用确认；等待确认时保留草稿，不标为已应用 |

普通保存后仍停留在编辑器，稍后可以从应用页的草稿入口继续。**⌘S / Ctrl+S** 与
“保存到 OcHub”相同，包括原始编辑器内的无效文本。OcHub 不会在每次按键时自动保存。
离开有修改的编辑器时，可选择继续编辑、放弃修改或保存并离开。

“草稿已保存”“配置已写入”和“目标客户端已读取”是不同状态。应用失败时查看具体阶段；
保留的草稿可继续修正。远端断线会保留当前输入，重连前不能保存或应用；不要把内存中的
输入当作已经保存的草稿。

只有完整写入回执可用时，结果区才提供**撤回本次应用**。撤回会核对当前状态是否仍与本次
写入后相符；之后出现外部修改就拒绝覆盖。对多个连接共用的文件，即使是另一连接的新改动
也可能阻止撤回。官方凭据、网关准备或外部导入等不具备完整恢复范围时，不显示该入口。

## 连接的日常操作

| 操作 | 适用场景 |
| --- | --- |
| 编辑 | 修改地址、密钥、模型、备注或高级字段 |
| 拖动排序 | 调整列表和系统菜单中的显示顺序 |
| 复制到应用 | 用目标应用格式创建独立草稿，不改动原连接；在目标应用页检查并应用 |
| 添加到工具 | 预先写入工具，但保持当前连接不变 |
| 切换 | 立即把它设为当前连接 |
| 从工具移除 | 保留 OcHub 数据，只移除工具侧配置 |
| 删除 | 从 OcHub 永久删除连接 |

## 官方登录

“使用官方登录”不会写入第三方 Base URL 或 API Key，而是沿用工具自身的登录状态。适合：

- Claude Code 或 Codex 已完成官方账号登录。
- 临时从第三方 API 切回官方服务。
- 希望保留工具原生的账号和订阅能力。

对于 Codex，`auth.json` 和 `config.toml` 都属于当前连接版本。任一文件在 OcHub 外被修改后，
如果希望保留修改，应在切走前查看差异并保存为新版。

## 应用专属设置

在应用页面右上角打开“应用设置”：

| 应用 | 主要设置 |
| --- | --- |
| Claude Code | 自定义配置目录 |
| Codex | 统一会话历史、迁入既有会话、自定义配置目录 |
| OpenCode | 自定义配置目录 |
| OpenClaw | 自定义配置目录 |
| Hermes | 自定义配置目录 |
| Grok Build | 自定义配置目录 |

自定义目录会影响配置、MCP 或会话历史的读取位置。保存后建议重启 OcHub 和目标工具。

Codex 历史选项使用复选框，勾选或取消后立即保存。开启“统一 Codex 会话历史”后，
才会显示“迁入既有 Codex 会话”。

目录输入在点击“保存目录”前属于草稿，调整历史复选框会保留这段输入。如果保存过程中
继续修改目录，请再点一次“保存目录”，写入后续输入的内容。

## 编辑器中的检查工具

**配置文件**显示候选配置和路径，最终文件还要在目标环境中与已有配置合并。
它不等于无条件覆盖整份目标文件。长行可以横向滚动。

点击**编辑**修改原始文本，**更新编辑内容**会将可解析的内容合入表单，尚未写入应用。
**返回编辑器**会保留文本；解析失败时仍可保存草稿，切回结构化表单前需要修正格式。
未建模的配置键会保留，格式与注释能否原样保留取决于目标应用的格式与适配器。

**通用配置**是该应用的共享片段，同名键按实际合并规则覆盖连接值，并非默认值继承。
编辑共享片段会影响使用它的连接；保存草稿不会改共享内容，修改随明确应用操作提交。

受支持的内置应用还提供**测试 URL**、**拉取模型**和**查询余额**。它们分别检查 HTTP
响应、模型目录和兼容的余额接口，不等于一次实际模型请求成功。检查结果在修改配置后
需要重新确认；最终仍以目标工具的真实请求为准。

## 配置被外部修改

OcHub 会把每个当前连接视为一个已保存的配置版本。切换前，它会比较这个版本与磁盘上的
当前文件：

1. 查看并排文件差异。红色是已保存版本，绿色是当前文件。
2. 选择“保存为新版”，把当前文件存入当前连接后再切换；以后切回来时会恢复这个新版。
3. 选择“回退为旧版”，丢弃磁盘上的当前修改，恢复已保存版本后再切换。
4. 选择“取消”，OcHub 数据和当前文件都不会改变。

该流程适用于所有可读取实时配置的切换型应用，包括 Claude Code、Codex、Grok Build、
Kimi Code 和切换型插件。Codex 会把 `auth.json` 与 `config.toml` 分开展示；即使
`auth.json` 不是合法 JSON，其原始文本也会纳入差异，并可原样保存和恢复。

不要让 OcHub、cc-switch 和手工编辑器同时修改同一份配置。

## 验证新连接

在编辑器应用完成或切换已有连接后：

1. 查看生成的文件与路径。
2. 确认结果为“配置已写入”，或在外部应用完成导入确认；仅保存草稿还没有写入。
3. 完全重启目标工具。
4. 选择新的 Provider 与模型。
5. 发起一条短请求。
6. 检查工具错误、OcHub 用量或上游日志。

| 问题 | 常见原因 |
| --- | --- |
| 连接没出现在工具里 | 只保存了编辑草稿而未应用，或配置目录不对 |
| 一个连接覆盖了另一个 | 多连接共存应用使用了重复 Provider ID |
| 401 | API Key、环境变量或进程启动环境不一致 |
| 404 / 请求体错误 | API Backend、协议或 API 模式选错 |
| 模型可见但调用失败 | 模型 ID、上下文限制或权限不匹配 |
| 高级字段应用失败 | JSON/YAML 节点类型不正确；可先保存无效内容为草稿 |
